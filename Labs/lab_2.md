# Лабораторная работа 2. Контейнеризация ML-сервиса

## Цель работы

Научиться:

1. писать Dockerfile для ML-сервиса с учётом размера и слоёв образа;
2. использовать multi-stage build для оптимизации;
3. настраивать docker-compose

Берётся сервис на FastAPI из лабораторной работы №1, к нему добавляются Docker-файлы.

## Ход работы

### 1. Dockerfile

Соберите образ для сервиса из ЛР№1. Требования:

- зависимости ставятся до копирования кода приложения;
- используется multi-stage build: стадия сборки отделена от финальной стадии выполнения;
- модель скачивается при старте контейнера (веса не в git, не в образе).

### 2. docker-compose

Опишите `docker-compose.yml`, поднимающий сервис одной командой. Полезно даже для одного контейнера: фиксируем порты, volumes (например, для кеша модели, чтобы не скачивать заново при каждом перезапуске), переменные окружения.

### 3. Оптимизация образа

Сравните размер образа до и после оптимизации (multi-stage, `.dockerignore`, слои). Зафиксируйте в README или любом другом удобном для вас виде:

- размер базового образа;
- размер после оптимизации;
- как изменился размер? если не изменился, то почему?

### 4. Тесты внутри контейнера

Тесты запускаем внутри контейнера, не только на хосте:

```bash
docker build -t toxicity-service .
docker run --rm toxicity-service pytest tests/ -v
```

Если тесты проходят локально, но падают в контейнере (или наоборот) -- возможно, у вас разошлись окружения.

### 5. Безопасность образа

- контейнер не должен работать от `root` — создайте непривилегированного пользователя;
- при необходимости указывать секреты не прописывайте их напрямую в Dockerfile, можете воспользоваться [инструкцией](https://www.hostinger.com/au/tutorials/docker-build-secrets/#1) или любым другим удобным для вас методом.

## Что сдаётся

- `Dockerfile`, `docker-compose.yml`, `.dockerignore` в репозитории.
- Демонстрация на защите: сборка образа, запуск тестов внутри контейнера.

## Примерные вопросы

1. Структура Docker-образов: как кеширование слоёв влияет на скорость сборки, почему порядок инструкций в Dockerfile важен.
2. Multi-stage build: зачем нужен, как экономит место (что остаётся в финальном образе, а что нет).
3. Разница между образом и контейнером; основные команды (`build`, `run`, `exec`, `logs`, `ps`).
4. Зачем контейнеры запускают не от root, какие риски у запуска от root.
